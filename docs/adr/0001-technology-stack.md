# ADR-001: Technology stack

- Status: Accepted
- Date: 2026-10-27

## Context

Τι χτίζουμε;

Χτίζουμε μια πλατφόρμα απομακρυσμένης παρακολούθησης ασθενών με υπερταση. Ο ασθενής καταχωρεί τιμές πίεσης από το σπίτι και ο γιατρός βλέπει απομακρυσμένα την πορεία της υγείας του.

Οι απαιτήσεις που επηρεάζουν την επιλογή τεχολογιών είναι : 

- ** Ευαίσθητα δεδομένα: ** τα δεδομένα υγείας είναι προσωπικά δεδομένα και πρέπει να αποθηκεύονται και να διακινούνται με ασφάλεια (GDPR).
- ** Δεδομένα στον χρόνο: ** οι μετρήσεις είναι πολλές , μαζεύονται συνεχώς και αναλύονται ανά περίοδο (π.χ μέσος όρος 7 ημερών) .
- ** Διαλειτουργικότητα: ** το σύστημα πρέπει να μπορεί να ανταλλάσσει δεδομένα με αλλα συστήματα υγείας μέσω του προτοτύπου HL7 FHIR.
- ** Cloud Native: ** το σύστημα θα τρέχει σε cloud και πρέπει να στήνεται ίδιο σε κάθε περιβάλλον.
- ** Μαθησιακός Στόχος: ** το project φτιάχνεται από έναν developer με στόχο την εξάσκηση σε java , βάσεις δεδομένων και cloud- native ανάπτυξη.


## Decision

 ** Java 25 + Spring Boot 4.1:** Η Java κυριαρχεί στα enterpirse πληροφοριακά συστήματα και η πιο ώριμη υλοποίηση του FHIR (HAPI FHIR) είναι γραμμένη σε Java. Το Spring Boot δίνει έτοιμα ασφάλεια, πρόσβαση σε δεδομένα και παρακολύθηση. Διαλέξαμε τη 4.1 γιατί η σειρά 3.x δεν λαμβάνει πλέον δωρεάν ενημερώσεις ασφαλείας , και τη Java 25 ως την τρέχουσα LTS έκδοση.
 ** PostgreSQL  + TimescaleDB:** Η PostgreSQL είναι ώριμη ,Open-source, σχεσιακή βάση με transactions και constraints, κατάλληλη για ευαίσθητα δεδομένα. Η επέκταση TimescaleDB προσθέτει αποδοτική διαχείριση time*series δεδομένων, οπότε οπότε ασθενείς και μετρήσεις ζουν στην ίδια βάση και συνδέονται με απλή SQL.
 ** Flyway:** κάθε αλλαγή στο σχήμα της βάσης γίνεται με εκδοσιοποιημένο SQL script. Το Hibernate μόνο ελέγχει το σχήμα ('ddl-auto:validate'), δεν το αλλάζει.
 ** Maven με maven Wrapper: ** όποιος κάνει clone χτίζει την ίδια ακριβώς έκδοση του Maven χωρίς εγκατάσταση.
 ** Docker / Docker Compose: ** οι υποδομές (βάση, και αργότερα Keycloak και Kafka) σηκώνονται με μία εντολή , ίδιες τοπικά, στο CI και στο Cloud. 
    Integration tests τρέχουν σε πραγματική PostgreSQL μέσω Τestcontainers.
 ** Github Actions:** κάθε push χτίζεται και ελέγχεται αυτόματα.

## Alternatives considered

- **Node.js / TypeScript:** ήδη γνωστό, άρα πιο γρήγορη ανάπτυξη, αλλά
  δεν εξυπηρετεί τον μαθησιακό στόχο και έχει λιγότερο ώριμο οικοσύστημα
  για FHIR.

- **Spring Boot 3.x:** περισσότερα παραδείγματα στο διαδίκτυο, αλλά εκτός
  δωρεάν υποστήριξης από τον Ιούνιο του 2026.

- **MongoDB:** τα δεδομένα μας είναι έντονα σχεσιακά (ασθενής, ιατρός,
  συναίνεση, μετρήσεις) και χρειάζονται constraints και transactions.

- **Ξεχωριστή time-series βάση (π.χ. InfluxDB):** θα σήμαινε δεύτερο
  σύστημα για συντήρηση και δύσκολη σύνδεση μετρήσεων με ασθενείς.

- **Gradle:** ισοδύναμη επιλογή, αλλά το Maven είναι πιο διαδεδομένο και
  πιο απλό για ξεκίνημα.

## Consequences

Θετικές:
- Στοίβα που χρησιμοποιείται ευρέως σε enterprise και συστήματα υγείας.
- Μία βάση για όλα τα δεδομένα, με SQL.
- Ίδιο περιβάλλον σε ανάπτυξη, CI και cloud.

Αρνητικές:
- Μεγαλύτερη καμπύλη εκμάθησης από ένα γνωστό εργαλείο.
- Το Spring Boot είναι βαρύτερο σε μνήμη και χρόνο εκκίνησης από το Node.js.
- Το Docker είναι απαραίτητο για ανάπτυξη (στα Windows μέσω WSL2).
- Ανοιχτό ερώτημα για τη Φάση 5: αν το managed PostgreSQL του Azure
  υποστηρίζει TimescaleDB.
